# Runtime instances are built at the composition root; Chat Persistence is the one root-initialized holder

ADR-0016 and ADR-0030 build the Foreground Gate and the Summarizer Queue at the composition root and hand them down as explicit arguments, while every other runtime instance — the Summarizer Dispatch (the request runner and its live-request set), the Usage Ledger, the memory-injection slot writer, and the Reroll Tail flag — lived as bare module state no root ever initialized, so `index.js` showed half the object graph and a test could only reset that state by reaching into the module. Those instances now follow the same rule: a `createX` factory returns a plain object of functions, the root builds one, and consumers receive it as a named argument — the three static callers of `callSummarizer` take a `dispatch` function as the Continuity Audit already does, the Usage Ledger rides the Call Session facts so the Route Series records without module state, and the Reroll Tail is recorded by `beginGeneration` and read from the gate. Chat Persistence is the deliberate exception: `persistChatState` is imported by six core modules and `flushPendingChatSave` by three, so threading a debounce timer through nine signatures that otherwise never use it would re-create the parameter churn ADR-0030 removed; it stays a module holder the root initializes once with the host save functions, which is the one seam a test fakes.

## Considered Options

- **Thread Chat Persistence like the others** — rejected: nine call sites gain a dependency they only forward; the holder gives the same single owner and the same test seam at one `init` call.
- **One runtime bundle (`{ dispatch, usage, persist, injection }`) passed everywhere** — rejected: it re-creates the metadata bag ADR-0008 and ADR-0023 deleted, and every test must build a whole runtime to exercise one seam.
- **Root-initialized holders for everything (the Refresh Port idiom)** — rejected: a holder keeps module state, so a test still shares one instance per module instead of constructing its own, which is the testability the move exists to buy.
- **Leave the module singletons and document them** — rejected: every future architecture review would re-flag them, and the two-tier ownership is what made the graph hard to read.
