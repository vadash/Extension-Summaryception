# 0016 — One prompt-mutation protocol at the Foreground Gate

Every prompt slot write and every commit crosses the Foreground Gate (src/core/summarizer-commit.js): the gate — not the writer — decides whether the work runs now, queues until the freeze lifts, or requeues as stale. The two renderers, `updateInjection` and `updateContinuityInjection`, are plain writers with no freeze self-check; the composition root wraps the Refresh Port effects `injection-refresh` and `continuity-refresh` in `runPromptEffect`, and the committed-injection update keeps its existing `runPromptEffect` path. Reroll ordering moves into the gate: `beginForegroundGeneration({ beforeFreeze })` runs the sync hook first, then reasserts the committed injection, then sets the freeze — so a regenerate or swipe drops the rerolled reply's Continuity Checkpoint (ADR-0014) and refreshes the slot inside the gate's pre-freeze window, not through entry-event sequencing.

Behavior change (intended): injection and continuity refreshes requested mid-generation now queue and apply at `endForegroundGeneration` instead of being skipped. Slot content during a generation is unchanged. This closes a hole in the old two-protocol split: `isPromptMutationFrozen` reports true for the whole stale-heal window, so a renderer self-check dropped a reroll's pre-freeze refresh exactly when the ordering mattered most.

Rejected alternatives: slot-writer enforcement in the foundation facade — the freeze is core policy, a facade boolean hides the drop reason, and every call site still needs a wrapper; renderer-internal gate routing — each renderer calling `runPromptEffect` through the registered callback registry makes the gate re-entrant on itself and splits the queue-vs-run decision across two layers; keeping the two protocols documented — the renderer self-check is what shipped the stale-heal hole, so documenting it preserves a bug.

Consequences: refreshes requested while a generation is frozen land in one flush at generation end, the path commits already use; the renderers lose their `summarizer-commit` imports, so the feature layer no longer depends on core run control; the gate module keeps its interface — export list unchanged, `recoverStalePromptFreeze`, `canStartPromptMutation`, and `queuePromptEffect` stay, and no module split. The `beforeFreeze` hook is sync-typed, so a heal can never interleave between the pre-freeze refresh and the freeze.
