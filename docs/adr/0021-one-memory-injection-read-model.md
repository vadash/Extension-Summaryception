# 0021 — One Memory Injection read model builds and measures the prompt slot

`src/core/memory-injection.js` owns what ships in the prompt slot behind two calls: `buildInjection(layers, settings)` returns `{ text, parts }` synchronously, and `measureInjection(injection)` returns the token cost of the text it was handed. `src/core/memory-budget.js` is deleted. `Memory Injection` and `Memory Body` are now vocabulary (CONTEXT.md); ADR-0020 named this opportunity and recorded it as out of scope, and nothing here changes the Layer 0 Run.

**Two jobs were sharing one name, not two derivations of one job.** The repo had a shipped injection — compact anchors, template-wrapped, measured for the Context Budget bar — and a summarizer `Memory Body` — full anchors, bare, never wrapped. The old `buildMemoryInjection` was the second one, despite the name, and `buildEffectiveMemoryText` was the first. The read model keeps them apart by intent: `buildMemoryBody` feeds `buildFullContext` and the pending Layer 0 context; `buildInjection` feeds the slot writer, the macro, the slash-command preview, the settings preview, and the budget bars.

**The duplicate was not the renderer, it was the convention.** `getEffectiveMemoryUsage` already built the same parts, rendered the same template, and returned the resulting `text` — a field no caller ever read — while `buildEffectiveMemoryText` derived the same string a second time from the same layers with the same `compactAnchors: true`. The two agreed because both call sites happened to pass the same flag, not because anything enforced it: the preview panel and the shipped prompt were one edit away from disagreeing silently. `measureInjection` takes the **built injection** rather than the layers, so it can only count text that was built — the agreement is now structural, and a test can state it (`measureInjection`'s total equals `countTextTokens(injection.text)`).

**The seam is build-sync, measure-async, and it stays that way.** Text assembly is pure string work; token counting needs the host tokenizer and is therefore async. The slot writer is synchronous and runs inside ADR-0016's Foreground Gate protocol — from the commit callback and from Refresh Port effects, whose `fire()` discards its promise. One async read model returning `{ text, usage }` was rejected: it would make every slot write await a count it does not display, and would turn an unhandled rejection in an effect into a silently skipped injection. A `measureLayers(layers, settings)` compositor was rejected too: a second way from layers to a number is a second place for the flags to drift; the promotion planner and candidate write the explicit `await measureInjection(buildInjection(...))` at their four sites, where the hypothetical layer set is the point.

**One build, one measure, per refresh.** `updateUI` built the injection three times and counted it twice: the advanced memory card, the Easy memory card, and the preview each derived it, and the preview ran its own `countTextTokens` over the same string `getEffectiveMemoryUsage` had just measured. It now builds once, measures once, and hands `{ injection, usage }` to both budget cards and the preview; `renderPreview` no longer counts anything. Nothing is cached across refreshes: consistency comes from one code path, not from one cached value keyed by Mutation Epoch, which would add staleness to a problem that was never about performance.

**Display policy stays in entry.** No memories ⇒ `text: ''`, and the injection template is suppressed entirely rather than wrapped around an empty body. That rule belongs to the module; the placeholders a user reads — `(No summaries yet)`, `(empty - no summaries yet)`, `(none yet)` — stay at their call sites, per ADR-0019. `assembleSummaryBlock` is deleted; entry imports the read model directly instead of routing through a feature pass-through that only forwarded store reads.

Out of scope, deliberately: `estimateContextPreview` (a request-context estimate, not the injected memory), the Continuity Block's own injection path, and any change to memory placement or role mapping.

Consequences: `usage` loses its `text` field, which no caller read. The injected string is unchanged in every path, so no user-visible behaviour moves. `CONTEXT.md` gains Memory Injection and Memory Body. `tests/memory-injection.test.js` repoints at the new module and pins the build/measure contract, including the empty-injection and no-template-suppression rules.
