# Auditor emits semantic flags; JavaScript owns the state rulebook

The Continuity Auditor judges each bond pair per Exchange and emits only the five booleans (positive_interaction, slight, insult, betrayal, apology); every counter, conversion, and threshold — bond/sparks/grudge arithmetic, the %5 sparks-to-bond and %3 grudge conversions, the bond-to-gate ladder, and the derived `turn_count` — is computed by JavaScript in `applyPairFlags` / `resolveGate` / `deriveTurnCount` (src/foundation/continuity.js). A language model doing the math directly was rejected: numeric drift across full-state rewrites compounds silently, the ladder would have to be re-taught in every prompt (and would drift from the injected Continuity Block), and boolean output is mechanically validatable while prose arithmetic is not — the two-tier section verdicts and one-shot repair in the runner depend on that. Consequence: the stored Continuity State is the single source of truth for all numbers, the Auditor prompt can stay small and language-agnostic, and changing the rulebook (caps, ladder, conversions) is a code change with tests, never a prompt change.
