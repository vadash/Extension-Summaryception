# 0022 — Continuity Coverage derives the marks; the marker is a DOM adapter

The Continuity Mark read model moves into `src/core/continuity-coverage.js`: `deriveContinuityMarks(chat)` returns `{ markedIndices, liveIndex }` beside the coverage anchor, and `src/entry/continuity-marker.js` keeps only the DOM toggle. One module now owns every fact derived from Continuity Checkpoint payloads; the audit lifecycle, the Continuity Block, and the chat-view marks all read it.

**The rule was implemented twice; the sync was a comment.** The newest-payload-wins walk existed as coverage's back-to-front `findLiveCheckpoint` and as the marker's forward walk in the entry tier, with the marker's doc comment pointing at the walk it must keep matching. The one deliberate divergence — the marker keeps reading the chat view while the coverage anchor excludes the Reroll Tail — was encoded only as the asymmetry between the two implementations, and two test files pinned the same rule against both. `deriveContinuityMarks` now rides `findLiveCheckpoint(messages, -1)` for the Live Mark, so the divergence is one explicit argument (no exclusion) instead of a second walk, and the payload-presence scan for `markedIndices` is the trivial filter beside it. One `isAssistantMessage` predicate (continuity-state.js) serves every chat walk, so the assistant-reply test exists once.

**A marks field on the coverage result was rejected**: a DOM toggle would then hold the whole coverage interface, and the prompt-view/chat-view duality would become an options fact (`rerollTail: false`) on a result that otherwise means the prompt view. Exporting only the live anchor was rejected too: the payload-presence knowledge would stay split across the seam, the weaker form of the same defect.

**Turn Count regains its named authority.** CONTEXT.md and ADR-0006 cite `deriveTurnCount` (src/core/continuity-state.js); the symbol did not exist — the derivation lived inline in the coverage read model. It is restored in continuity-state.js as the authority coverage consumes; the derivation is unchanged (assistant turns in the chat), so the Conversion multiples and `prior.turn_count` see identical input.

Consequences: zero behavior delta — the same `markedIndices`, `liveIndex`, and `turnCount` on every path; the Continuity Block reads coverage, not marks, so injected text cannot move. `tests/continuity-marker.test.js` pins the derivation at its new core seam. ADR-0017 stays current: the module-state reroll flag, newest-payload-wins, drop-at-generation-start, and prompt-view placement are untouched — this document decides where the walk lives, not what it computes.
