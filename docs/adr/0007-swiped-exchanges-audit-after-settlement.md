# Swiped Exchanges audit after settlement, not at swipe time

A swipe or continue trigger never dispatches the Continuity Auditor; it only rewinds `anchor_sc_id` one Exchange (`rewindContinuityAnchor`, src/core/continuity-runner.js) when the anchor points at the swiped message itself — repeat swipe events for the same draft id are therefore idempotent, a chat with no predecessor assistant message rewinds to `''`, and the rewind bumps the store mutation epoch before persisting like any snippet mutation (ADR-0003). The swiped-for text is audited as part of the next `normal` trigger through the Catch-up Window, once the user settles on a variation. Auditing on every swipe click was rejected because a settled Exchange would burn several extraction calls on drafts the user discards; leaving the swiped text outside coverage was rejected because it silently contradicts the Exchange definition (a user message plus its latest swipe variation) in CONTEXT.md; unconditionally resetting the anchor to `''` was rejected because it destroys coverage of everything the state already audited. Consequences: the Continuity Block's depth widens by the rewound Exchange (uncovered span) until the next normal audit re-covers it, and an unsettled swipe loop delays audit coverage of the Exchange rather than widening it. The rewound Exchange never double-counts: `turn_count` re-derives from the chat at every audit; the anchor bounds coverage only, never accumulation.
