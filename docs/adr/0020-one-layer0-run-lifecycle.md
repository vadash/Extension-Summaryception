# 0020 — One Layer 0 Run lifecycle owns every Layer 0 commit

One module (`src/core/layer0-run.js`) turns one or more Passages into committed Layer 0 Snippets behind one interface: `runLayer0(routePlan, notify)` returns a Run Outcome and never throws. It replaces `summarizeBatchFromTurns` and `summarizeAtomicLayer0Partitions`; the engine's `commitRoutePlan` dispatch on `commitMode` disappears and both engine sites — the auto cycle and the manual loop — call the run directly. A Passage is the run's unit (CONTEXT.md, Passage): Passage 0 is dispatched with `buildFullContext(0)`, later Passages with the accumulated pending context, which is the one rule both old paths already followed.

**The collaborators were shared; the loop and the verdict were not.** `createBatchProgress`, `runLayer0Summarization`, `commitLayer0Job` and `summarizeSafely` already existed, so the deletion test is not "delete a collaborator and everything reappears". What was copied was the unit loop with its freshness check, the verdict table (the single-Batch path folded `aborted` into `failed`, the atomic path kept it), and the settlement itself — six `settle` call sites spread across four collaborators, with the exactly-once invariant surviving as comments ("settle it before the exception reaches summarizeSafely", "Every failure routes through the owner so the run's handle settles exactly once"). Answering "which paths settle the handle?" meant reading all four collaborators and both loops.

**The Route Plan is the argument.** `SummaryRoutePlan` already carries `commitMode`, `batchTurns`, `partitions`, `sourceEndIdx` and `totalBatches`, so the run needs no second parameter and the engine keeps its existing role of building plans. Prebuilt units (the shape this deepening was first described with) were rejected: a Passage plus caller-supplied context puts the context-accumulation rule back in each caller, which is the copying this change removes. One interface per commit mode was rejected for the same reason — two entries sharing collaborators is the state being replaced. The run also absorbs the pre-run duties that lived above it: stable-ID assignment, the eligibility filter, the boundary-to-`passageStart` derivation, and the Ghosting repair for a run with nothing to cover, whose basis is `routePlan.batchTurns`.

**Verdicts state what happened; callers stop inferring.** `processStrategyBatch` set `success: outcome.status === 'completed'`, and `applyManualLoopStep` counted a batch whose boundary did not move as `tally.blocked` — the manual loop re-derived the Foreground Gate's verdict from a side effect it happened to observe. A commit that `commitWhenSafe` queues is now `blocked` at the run level (the store has not changed; the flush settles it), `aborted` stays `aborted` at every run level instead of being folded into `failed`, and `processRoutePlan` no longer logs `blocked` or `idle` as "Route batch failed" — waiting and having nothing to do are not failures. The post-batch gate check stays: it is the only thing catching a freeze that begins after an applied commit.

**A total contract.** The `catchExceptions` option is gone. Both production call sites passed `true`; the `false` default was reachable only from tests, and its whole effect was converting a throw into `{ status: 'failed' }`. The run returns an outcome like every other run level, and the two tests that asserted a rejection now assert the failed outcome alongside the same rollback assertions. `options` as an argument went with it: `{ notify }` was a bag of one, so the adapter passes positionally, as the other core seams already do.

**Two behaviours are load-bearing and stay exactly as they were.** The freshness check runs before each Passage after the first and compares the **run's first** basis, not the previous unit's, so any store or chat change since the run began aborts the remaining Passages instead of burning doomed requests; and the commit re-validates every entry, which is what makes a queued commit safe to apply at flush time, long after its Passages were validated.

**One behaviour delta, recorded.** With one pre-run, a run with no work to cover now repairs Ghosting ownership on every route, where only the turns-based path did before. The reach is narrow — a ready cache-friendly plan's `batchTurns` are past the boundary, so the repair range is empty and only the deferred chat persist happens — and the repair is idempotent, but it is a delta rather than "no behaviour change" and is recorded as one.

Out of scope, deliberately: Snippet Regeneration's own capture-dispatch-commit (an existing snippet through the Snippet Commit seam, with no snapshot and nothing atomic), the Promotion Drain's loop, and the Memory Injection and prompt-prefix opportunities of the same review.

Consequences: `summarizer-batch.js` becomes `layer0-run.js`; `CONTEXT.md` gains the Layer 0 Run term, repoints Batch at `SummaryRoutePlan.batchTurns`, and points Passage at the run module; `tests/summarizer-batch.test.js` becomes `tests/layer0-run.test.js` and drives one Passage, N Passages all-or-nothing, abort-on-mutation, and the queued commit that stays open until flush. ADR-0016 (the gate) and ADR-0019 (the outcome vocabulary) are unchanged: this document decides where the gate's verdict is read and who produces the outcome, not what either means.
