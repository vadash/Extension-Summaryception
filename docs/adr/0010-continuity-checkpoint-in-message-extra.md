# Continuity Checkpoint in message extra, not chat metadata

The Continuity State moves out of chat metadata into per-message Continuity Checkpoints: every successful audit writes the full state, the audited Exchange's `sc_id`, and a hash of the reply text into that reply's message `extra`; one checkpoint per Exchange, no pruning. The live state becomes a read model: walking checkpoints oldest-first, a checkpoint counts only while every earlier checkpoint counts, its `sc_id` still resolves in the chat, and its hash matches the reply's current text — the newest valid checkpoint wins. Deletion, swiping, regenerating, and forking therefore need no rewind events, no `continuityRevert` snapshot, and no anchor reconciliation; the first broken link drops the read model back to the checkpoint before it, and swiping back to the audited text restores the chain automatically. This supersedes the rewind mechanics of ADR-0007 on implementation. It also fixes a case the shared slot could not: deleting an Exchange older than the anchor contaminated the state permanently, because no rewind fired for an anchor that still resolved. Delta chains over checkpoints were rejected: replay logic and a single corrupt delta poisoning the chain reintroduce exactly the complexity this change removes.

The in-flight audit abort at generation start is dropped. ST's `generateRaw` takes no AbortSignal (src/core/connection-default.js), so the abort never saved tokens on the default route — it only discarded an already-finished request, and ST's global `GENERATION_STOPPED` broadcast (fired by the user stopping any generation) killed default-route audits collaterally either way (verified against ST script.js:3946-3959). Audits now always run to completion and attach at settle when the target message still exists and its hash matches; the chat-switch write guard around the save stays. Staleness becomes derived, not stored: the injected block shows the stale marker whenever the newest valid checkpoint's Exchange is not the chat's last Exchange, so the spec §7 freeze path and the `stale` field die.

Consequences: existing chats cold-start their continuity state (no migration shims per repo rules); chat files grow by the state size (~1–3 KB) per Exchange, unbounded, because pruning would kill the swipe-back restore; triggers stay unchanged — audits fire on settled replies only, and the Catch-up Window still bounds re-coverage at four Exchanges. Interleaved audits need no rebase step: an audit dispatched while an earlier one is still in flight reads the same prior checkpoint at dispatch, so its Catch-up Window re-covers the predecessor's Exchange and the newest attached checkpoint wins on read; any attach whose chain position a mid-flight deletion broke is discarded by the chain rule itself.
